# Private task recovery

Runner readiness requires an explicit `CODEX_RECOVERY_ROOT`: an existing, dedicated directory owned by the runner UID with mode `0700`, outside Git checkouts, the task sandbox's writable checkout and temporary roots, `RUNNER_WORKSPACE`, and `RUNNER_TEMP`. There is no default, automatic provisioning, chmod, pruning, or runner activation. An empty dedicated directory is accepted; occupied general directories and ambiguous layouts are rejected. The store uses private `0600` files and a versioned layout. A runner administrator must provision persistent storage and access controls separately.

Before every self-hosted checkout, including read roles and preflight, trusted inline workflow code refuses missing/unsafe stores, an `ACTIVE` marker, or exhausted record capacity. This gate checks the recovery invariant; its success does not establish runner readiness or process quiescence. An unconfigured store intentionally blocks preflight before checkout.

A task writes `ACTIVE` before preparation or the model. Receipts retain task/approved-contract context, branch/base/start/current revisions, phase/exit/signal, binary staged and unstaged patches, regular untracked files with modes, artifact hashes, and incremental Git bundles when committed work has no confirmed push. Push and PR operations persist `not_attempted`, `attempted_unconfirmed`, or `confirmed` before and after calls. An ambiguous response remains quarantined. Confirmed pushes describe command acknowledgement, not independent remote verification.

Raw Codex stdout/stderr, whitespace diagnostics and final messages stay in this private store before existing publication gates run. A child-only file-size limit bounds raw output generation; it also limits regular files written by the child. Capture is bounded to 25 MiB and 100 files per record, 100 records per store, and 32 capture/transition events. Evidence is content-addressed and hashed. A failed or incomplete capture leaves `ACTIVE`; credential-header removal still runs, while destructive checkout cleanup and reuse are blocked. Fully captured success or ordinary failure retains evidence and releases `ACTIVE` automatically. Queue cleanup first requires the child's quarantine to be released, then captures its own checkout before reset/clean/branch replacement.

Recovery inspection and restoration are owner-supervised: verify receipt/artifact hashes, restore the pinned Git baseline, apply the staged binary patch with `git apply --index`, apply the unstaged patch, and recreate each regular untracked file using its recorded path, bytes and mode. A bundle records its prerequisite revision and can be verified/fetched in a disposable checkout. Resolve ambiguous external writes against live remote state before releasing quarantine. There is deliberately no automatic release or prune command for incomplete records.

These are snapshot and final-state recovery checks. They do not preserve every transient or ignored write, isolate process descendants, prove credential-pattern scans are secret-free, or qualify an unattended production runner. Private recovery content must never be copied into progress comments or public artifacts. Existing intentional final-message publication gates still apply.
