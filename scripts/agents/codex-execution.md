# Explicit Codex execution settings

The three Actions role-launch steps require `CODEX_TASK_MODEL` from `vars.CODEX_AGENT_MODEL`, `CODEX_TASK_REASONING_EFFORT` from `vars.CODEX_AGENT_REASONING_EFFORT`, and the source label `github-actions-vars`. No defaults, variable creation, model fallback, automatic escalation or persistent configuration changes occur. The label does not identify whether GitHub resolved an organization, repository or environment variable. Existing owner/task, visibility, scope, sandbox and recovery gates still apply.

The checked-in policy separates the advertised native catalog fetched on 2026-10-25 (cache client 0.164.0) from the separately observed CLI 0.163.0. It retains the global Luna/Sol/Astra allowlist; this first unattended implementation accepts Luna through `max` and Sol through `ultra`, and rejects Astra because it has no task-specific authorization path. These are policy/catalog checks, not proof of remote support or account entitlement.

The wrapper freezes helper/policy/settings/identity and exact argv digests, supplies `--model`, a quoted `model_reasoning_effort` config, `--json`, and the existing `--ignore-user-config`. The private intent records requested and authorized settings with `invoked: null`. A small direct-child launcher records OS process start on its spawn event; this does not prove backend acceptance. It forwards HUP/INT/TERM to that child, preserves exit/interruption evidence, and adds no retry, fallback, process-tree isolation or new timeout. Existing shell output limits and role timeouts remain.

The bounded execution JSON stays under private `TMP_ROOT` and is captured through F3's existing hashed artifact mechanism. Before launch and before later publication/write actions, the wrapper verifies the captured manifest and exact retained execution-object bytes against the parent-held digest. Missing required evidence or a digest/persistence failure quarantines recovery. F3's budgets and helper are unchanged.

Observed model and effort remain null: no reliable telemetry for them is recognized here. Usage is only CLI-reported data from a single top-level JSONL `turn.completed` event with nonnegative safe-integer fields, line/event provenance and a stdout digest. Missing fields stay null; malformed, truncated, duplicate-key, ambiguous or unsupported usage stays unknown and does not fail valid work. Assistant text and stderr are never scraped. Launch elapsed time and exit status describe the local process; billed cost stays null. The recognized event shape follows [official non-interactive documentation](https://learn.chatgpt.com/docs/non-interactive-mode).

The strict development-learning schema remains unchanged. An operator can bind a retained private execution object through its existing `evidence.path` and `evidence.sha256` fields; no richer fields are injected into that schema and no learning proposal is activated automatically. No real model call or runner activation is part of these offline checks.
